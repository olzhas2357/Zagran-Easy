# Лаборатория иероглифов

Маршрут: `/hanzi-test`. Запуск: `npm run dev`, затем открыть этот путь на порту сервера. Во время реализации сервер запущен на http://localhost:3001/hanzi-test.

Выбран отдельный маршрут вне `/staff`: кабинет требует серверную сессию и обращение к backend. Лаборатория работает без авторизации и backend; индексация отключена через metadata robots. Это временная публично доступная страница, а не закрытый кабинет.

## Реализация

- npm, `hanzi-writer` 3.7.3. Код библиотеки подключён только из npm.
- `app/hanzi-test/page.tsx`: маршрут и metadata.
- `components/hanzi/HanziLab.tsx`: клиентская лаборатория, выбор символа, демонстрация, практика, сложность, результат и история последних пяти завершений.
- `components/hanzi/character-data.ts`: заменяемый адаптер загрузки одного JSON с jsDelivr. Тайм-аут 15 секунд, отмена запроса, проверка структуры, ошибка и повторная загрузка. `all.json` не используется.
- `package.json`, `package-lock.json`: зависимость.
- `docs/hanzi-test.md`: отчёт и сценарии проверки.
- Next.js при запуске dev автоматически создал `AGENTS.md` и `CLAUDE.md` с инструкциями для агентов.

Существующие страницы, авторизация и пользовательские изменения в PROMPT.md и prompts не изменялись.

## Жизненный цикл

Экземпляр создаётся в useEffect после появления контейнера. Контейнер предварительно очищается; каждый запуск эффекта получает отдельный DOM-узел. При смене символа, режима или сложности упражнение пересоздаётся. Cleanup отменяет quiz, приостанавливает анимацию, отменяет запрос и таймер, отключает ResizeObserver и очищает контейнер. Флаг disposed защищает от запоздавших ответов при Strict Mode; номер запуска quiz защищает от callbacks предыдущей попытки. Размер меняется через updateDimensions без сброса текущего прогресса.

## Возможности и проверки

Подключены animateCharacter, pauseAnimation, resumeAnimation, showCharacter/hideCharacter, showOutline/hideOutline, quiz и его onMistake/onCorrectStroke/onComplete. Ручная подсказка использует highlightStroke, который не отменяет quiz. Автоматические подсказки и leniency задаются выбранной сложностью. Загрузка использует onLoadCharDataSuccess/onLoadCharDataError.

## Сценарии ручной проверки

1. По очереди выбрать все семь символов; проверить единственное изображение иероглифа, pinyin, перевод и номер задания.
2. Запустить анимацию, поставить на паузу, продолжить. Переключить видимость символа и контура.
3. В практике нажать «Начать писать», нарисовать неверную черту: счётчик ошибок должен вырасти. Воспользоваться ручной подсказкой, затем написать правильную черту и закончить символ.
4. Проверить результат: количество черт, ошибки, время, max(0, 100 − ошибки × 10), предупреждение о тестовой оценке. Выполнить шесть попыток: в истории остаются последние пять, общий счётчик сохраняет все завершения.
5. Во время практики сменить сложность, символ и режим: прежняя попытка не должна завершиться или попасть в историю. «Начать заново» сбрасывает ошибки и таймер. «Следующий иероглиф» циклически перебирает список.
6. Ввести пустую строку, латиницу, emoji, два иероглифа; проверить ошибку. Ввести один Han-символ. Для отсутствующих данных либо отключённой сети проверить ошибку загрузки и повтор после восстановления сети.
7. На телефоне проверить отсутствие горизонтального переполнения, рисование пальцем без прокрутки внутри квадрата и обычную прокрутку вне него. Во время упражнения изменить размер окна: прогресс должен сохраниться.
8. Переключить тему. В dev/Strict Mode быстро менять символы: SVG не должны дублироваться и старые ответы не должны менять новое упражнение.
9. Обновить страницу: история и результаты должны очиститься.

## Ограничения и следующий этап

Библиотека сопоставляет штрихи с данными выбранного символа. Это не распознавание свободного текста, оценка красоты письма, проверка произношения или переводчик. Pinyin и переводы семи примеров заданы вручную; для собственного символа они не определяются. Доступность символов зависит от набора данных. Документация: https://hanziwriter.org/docs.html.

В будущем для хранения попыток потребуются поля HanziAttempt (id, character, difficulty, totalMistakes, score, durationMs, completedAt), связь с пользователем и заданием, число правильных черт, версия формулы оценки и версия набора данных. Для аналитики подсказок можно добавить количество ручных/автоматических подсказок и ошибок по каждой черте. На этом этапе никакие данные в Supabase не отправляются и схема базы не создаётся.
