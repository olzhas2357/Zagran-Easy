# Parents: привязка детей

Родитель создаётся через существующий `POST /users` с `role: parent`.
После создания админ-панель открывает редактирование пользователя, где дети
привязываются отдельно. Список студентов загружается со всех страниц API.

Backend: `/Users/olzhas/projects/zagran-easy-back/src/parents`.
Все маршруты требуют Bearer-токен; префикс `/api/v1`:

- `GET /parents/me/children` — собственные дети, роль parent.
- `GET /parents/me/schedule` — расписание собственных детей, роль parent.
- `GET /parents/:id/children` — admin/manager либо сам родитель.
- `POST /parents/:id/children/:studentId` — привязать, admin/manager.
- `DELETE /parents/:id/children/:studentId` — отвязать, admin/manager.

Создание и удаление связи идемпотентны. RPC обновляет `parents.children` и
`students.parent_ids` атомарно; проверяет роли, существование студента и
сериализует конкурентные изменения. Прямой вызов RPC доступен только service_role.
В кабинет возвращаются только учебные поля и имя ребёнка, без контактных данных.

## Установка

1. Применить миграцию `20260925094657_parent_child_links.sql` в Supabase.
2. Выпустить backend с обновлённым ParentsModule.
3. Выпустить frontend.

Миграция создаёт пустые записи для существующих родителей и добавляет триггер
для новых. Существующие связи не удаляются. Кабинет показывает ошибку API
отдельно от пустого списка. Платежи и задания остаются отдельной задачей.

## Расписание

Раздел `/parents/schedule` показывает дату, время по Алматы и статус занятия.
Для каждого привязанного ребёнка сервер объединяет индивидуальные занятия
из `scheduled_lessons` и занятия его активных групп из `lesson_sessions`.
Завершённые и отменённые занятия также отображаются. API возвращает только имя
ребёнка и минимальные поля расписания; состав группы, контакты и ссылки встреч
не передаются. Связь с детьми проверяется на сервере по текущему родителю.
Ошибка загрузки отличается от отсутствия детей или занятий.
Новая миграция для расписания не нужна; необходимо выпустить backend и frontend.

## Проверки

- Backend: `npm test -- --run src/parents/parents.service.spec.ts`.
- Backend production types: `npx tsc -p tsconfig.build.json --noEmit --incremental false`.
- Frontend: `npx tsc --noEmit`.
- SQL: `supabase/tests/parent_child_links.sql` после миграции. Проверяет
  создание записи родителя, обе стороны связи, повторные запросы, неправильные
  роли, права RPC и изоляцию RLS. Тестовые данные удаляются через ROLLBACK.
