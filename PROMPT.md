7. Расширение данных университетов

Я подготовлю список университетов. Архитектура должна поддерживать импорт и ручное редактирование.

Для университета добавить или проверить поля:

координаты latitude и longitude;

адрес;

google_maps_url;

youtube_url;

официальный сайт;

виртуальный тур;

галерея;

логотип;

тип университета;

языки обучения;

наличие гранта;

наличие общежития;

стоимость общежития;

регистрационный взнос;

медицинская страховка;

сроки подачи;

требования;

контакты;

преимущества;

ограничения;

дата последней проверки данных;

источник информации.

Программы, стоимости, intake, требования и стипендии желательно хранить не одним JSON-полем, а в отдельных связанных таблицах:

university_programs;

university_intakes;

university_requirements;

university_costs;

scholarships.

Предусмотреть импорт из CSV/XLSX:

предварительный просмотр;

сопоставление колонок;

валидацию;

отчёт об ошибках;

обновление существующего университета без создания дубликата;

журнал импорта.

Калькулятор не должен быть отдельной формой без сохранения результата.

Каждый расчёт должен быть связан с:

клиентом;

intake;

менеджером.

Функциональность калькулятора

Менеджер должен:

Открыть калькулятор из карточки клиента.

Выбрать один из добавленных клиенту университетов.

Выбрать программу и intake.

Автоматически получить известные стоимости из базы.

Добавить или изменить расходы вручную.

Выбрать валюту.

Указать используемый курс валюты.

Добавить скидку.

Настроить рассрочку.

Сохранить расчёт.

Создать новую версию без удаления предыдущей.

Сравнить расчёты разных университетов.

Сформировать клиентскую версию без внутренних комментариев.

Сгенерировать PDF или публичную ссылку.

Отправить предложение через WhatsApp вручную.

Все денежные значения хранить в точных числовых типах, не использовать float.

Зафиксировать курс валюты внутри сохранённой версии расчёта, чтобы старые расчёты не менялись при обновлении текущего курса.
